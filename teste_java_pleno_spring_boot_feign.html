Candidate: ____________________ Date: ____________________ Time: 30 minutes

Business Scenario

You work for a fictional digital bank. The platform has two independent microservices: Customer Service, responsible for customer information, and Account Service, responsible for bank accounts.

The Account Service needs customer information and must obtain it by calling the Customer Service through Spring Cloud OpenFeign.

Technical Requirements

  • Java 17+
  • Spring Boot
  • Spring Web
  • Spring Cloud OpenFeign
  • Maven
  • No database is required — use in-memory data

1. Customer Service

Create an independent Spring Boot application:

  • Port: 8081
  • Endpoint: GET /customers/{id}
  • Create 2–3 customers in memory.
  • Return HTTP 404 when the customer does not exist.

Example response:

{
  "id": 1,
  "name": "John Smith",
  "email": "john.smith@email.com"
}

2. Account Service

Create a second independent Spring Boot application:

  • Port: 8080
  • Endpoint: GET /accounts/{id}
  • Keep account data in memory.
  • Each account must contain an id, customerId and balance.

Example internal account:

{
  "id": 100,
  "customerId": 1,
  "balance": 1500.50
}

The endpoint should return:

{
  "id": 100,
  "balance": 1500.50,
  "customer": {
    "id": 1,
    "name": "John Smith",
    "email": "john.smith@email.com"
  }
}

3. Main Requirement — Feign Client

Account Service MUST call Customer Service using Spring Cloud OpenFeign. Do not duplicate customer name/email data inside Account Service.
Client → Account Service → Feign Client → Customer Service

Example Feign client:

@FeignClient(name = "customer-service",
             url = "${customer-service.url}")
public interface CustomerClient {

    @GetMapping("/customers/{id}")
    CustomerResponse findById(@PathVariable Long id);
}

Configuration:

customer-service.url=http://localhost:8081

Acceptance Criteria

  • Both applications start independently.
  • Customer Service exposes GET /customers/{id}.
  • Account Service exposes GET /accounts/{id}.
  • Account Service uses OpenFeign to call Customer Service.
  • The final response combines account and customer information.
  • Unknown customers are handled with an appropriate HTTP error.
  • Both projects build successfully with Maven.

Bonus Questions

  1. What happens if Customer Service is unavailable?
  2. How would you configure connection/read timeouts for Feign?
  3. How would you implement retry safely?
  4. How would service discovery work in Kubernetes instead of a hard-coded URL?
  5. What is the difference between Feign and WebClient?
